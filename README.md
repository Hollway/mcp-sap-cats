# mcp-sap-cats

MCP-сервер для таймшитов SAP — транзакция CAT2 / CATS. Задача **SAP-18862**.

Чтение и заполнение учёта времени через стандартные `BAPI_CATIMESHEETMGR_*`, вызываемые из собственного ICF-хендлера в целевой SAP-системе.

## Установка

```bash
npm install
npm run build
```

Скопировать `.env.example` в `.env` и заполнить. Сертификат корпоративного CA задаётся через `NODE_EXTRA_CA_CERTS` — без него самоподписанный сертификат SAP-хоста не пройдёт проверку.

## Тесты

```bash
npm test
```

Собирает проект и прогоняет `node:test` без обращения к SAP: схемы входных параметров, разбор сообщений и сквозной тест MCP-сервера против фейкового ICF-хендлера (`test/server.test.mjs`).

## Отладка

```bash
npm run dev
```

Откроет MCP Inspector: список инструментов виден сразу, вызывать можно руками, без перезапуска Claude.

Всё, что попадает в stdout, — это протокол. Отладочный вывод только через `console.error`.

## Подключение

```bash
claude mcp add sap-cats --scope user -- node C:\Tools\mcp-sap-cats\dist\index.js
```

В PowerShell вызывать `claude.cmd` (и `npm.cmd`), если политика выполнения блокирует `.ps1`-обёртки. `claude mcp add-json` там не подходит — PowerShell ломает кавычки в JSON-аргументе. Правка `claude_desktop_config.json` руками тоже не работает: приложение перезаписывает файл из памяти при перезапуске.

`.env` сервер читает сам, из каталога проекта рядом с `dist/`: Claude Code запускает `node dist/index.js` напрямую, без загрузки окружения. После пересборки MCP-сервер нужно перезапустить, иначе клиент видит старые описания инструментов.

Пишущие инструменты (`cats_insert`, `cats_change`, `cats_delete`, `cats_release`) auto-режим Claude Code по умолчанию блокирует как изменение общих ресурсов. Разрешение — `permissions.allow` в `.claude/settings.local.json` (не в git), заводится вручную.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `cats_whoami` | Мой табельный номер, ФИО и оргединица |
| `cats_projects` | Активные проекты и номера ТЗ для `ext.prjct`/`ext.rqsnb`, пара по ключу задачи Трекера (`ytr_key`) |
| `cats_read` | Вывод таймшита за период |
| `cats_capacity` | Свободные часы по дням с учётом календаря |
| `cats_validate` | Проверка записей без сохранения (`TESTRUN` + дневной лимит) |
| `cats_insert` | Создание записей, в том числе за несколько дней и по нескольким проектам сразу |
| `cats_change` | Изменение записей; утверждённая запись правится новой версией |
| `cats_delete` | Удаление записей — перевод в статус 60 «Сторнировано» |
| `cats_release` | Деблокирование; в этой системе сразу даёт статус 30 «Утверждено» |

Вместо пары проект + номер ТЗ в записи можно передать `ext.ytr_key` — ключ задачи Трекера, MCP сам найдёт пару. Без номера ТЗ обязательно описание `ext.descr`, как в CAT2.

Входные и выходные параметры — в `docs/solution.md`, контракт с ABAP-стороной — в `docs/handler-contract.md`.

Каждое обращение к SAP ограничено таймаутом (`SAP_TIMEOUT_MS`, по умолчанию 60 с). Ответ с `LR2` «Транзакцию блокирует пользователь» автоматически повторяется (`SAP_LOCK_RETRIES`, по умолчанию 2): хендлер при ошибке откатывает LUW целиком, а `cats_insert` идемпотентен по ключу, так что повтор ничего не задваивает.

## Сценарии (MCP prompts)

| Prompt | Что делает |
|---|---|
| `fill_week_like_last` | Заполняет неделю по образцу предыдущей в пределах свободных часов |
| `fill_gaps` | Закрывает недобор до нормы по рабочим дням периода одним проектом |
| `period_close_check` | Сводка перед закрытием периода: недобор, перебор, записи в статусе 10 |

Сценарии только собирают вызовы инструментов. Записывать что-либо они начинают только после того, как пользователь подтвердил итоговую таблицу.

## Состояние

Узел SICF `/sap/bc/zcats` заведён и активен, хендлер `ZCL_CATS_MCP_HANDLER` — в системе. Все девять инструментов (семь по ТЗ, `cats_whoami` и `cats_projects` сверх него) проверены на реальных данных, приёмка по требованиям ТЗ проведена — таблица покрытия в `docs/solution.md`. Автотесты: `npm test` (Node) и ABAP Unit в системе. Порядок работ, решения и открытые вопросы — в `CLAUDE.md`.
