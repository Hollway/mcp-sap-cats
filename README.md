# mcp-sap-cats

MCP-сервер для таймшитов SAP — транзакция CAT2 / CATS. Задача **SAP-18862**.

Чтение и заполнение учёта времени через стандартные `BAPI_CATIMESHEETMGR_*`, вызываемые из собственного ICF-хендлера в целевой SAP-системе.

Два способа запуска: у каждого пользователя свой процесс (stdio, раздел «Установка») или один общий сервер, к которому подключаются по HTTPS (раздел «HTTP-режим»). Если общий сервер в компании уже есть, ставить ничего не нужно — только подключить его в Claude Code (см. «HTTP-режим → Клиент»). В обоих случаях SAP работает под логином самого пользователя.

## Установка

Инструкция для пользователя, который ставит MCP-сервер себе (режим stdio). Сервер работает на вашей машине и ходит в SAP под вашим логином: видите и меняете вы ровно то, что вам доступно в CAT2.

### Что нужно заранее

- **Хендлер в той SAP-системе, где вы вводите часы.** Класс `ZCL_CATS_MCP_HANDLER` и узел SICF `/sap/bc/zcats` приходят одним транспортом. После импорта узел должен быть активен в SICF; если нет, сервер ответит 403 (см. «Если не работает»).
- **Пользователь SAP с доступом к CAT2.** Отдельных полномочий под MCP не нужно: записывать можно ровно тех, кого пускает CAT2.
- **Node.js 20 или новее** (`node -v`) и Claude Code.
- **Доверие к сертификату SAP-хоста** — он выпущен корпоративным CA. Либо корневой сертификат CA лежит в хранилище Windows (тогда хватит флага `--use-system-ca` через `NODE_OPTIONS`, Node 22.15+/23.8+), либо нужен его файл в формате PEM для `NODE_EXTRA_CA_CERTS`.

### Шаги

1. Получить код — клонировать репозиторий или скопировать папку, например в `C:\Tools\mcp-sap-cats`.
2. Собрать:

   ```bash
   npm install
   npm run build
   ```

   В PowerShell — `npm.cmd`, если политика выполнения блокирует `.ps1`-обёртки. За корпоративным прокси npm должен знать прокси (`npm config set proxy …` / `https-proxy …`).
3. Скопировать `.env.example` в `.env` рядом с `package.json` и заполнить: адрес узла, мандант, свой логин и пароль SAP, профиль ввода. Значения пишутся без кавычек; если в пароле есть « #», его берут в кавычки целиком, иначе остаток строки считается комментарием. Пароль лежит в файле открытым текстом — файл личный, никому не пересылать и не класть в git (`.env` уже в `.gitignore`).
4. Зарегистрировать сервер в Claude Code, передав ему доверие к сертификату SAP (см. «Что нужно заранее»):

   ```bash
   claude mcp add sap-cats --scope user -e NODE_OPTIONS=--use-system-ca -- node C:/Tools/mcp-sap-cats/dist/index.js
   ```

   С файлом сертификата вместо `NODE_OPTIONS=--use-system-ca` — `-e NODE_EXTRA_CA_CERTS=C:/Tools/certs/corp-root-ca.pem`. Переменная `NODE_USE_SYSTEM_CA=1` делает то же, что флаг, но появилась только в Node 22.19+/24.6+. Всё это Node читает только при старте процесса, поэтому в `.env` они не действуют. Пути — через `/`: так команда одинаково работает в PowerShell, cmd и Git Bash (в Git Bash обратные слэши съедаются). В PowerShell — `claude.cmd`. `claude mcp add-json` там не подходит: PowerShell ломает кавычки в JSON-аргументе. Править `claude_desktop_config.json` руками тоже бесполезно — приложение перезаписывает его при перезапуске.
5. Перезапустить Claude Code и попросить «кто я в SAP» — должен сработать `cats_whoami` и вернуть ваш табельный номер.
6. Пишущие инструменты auto-режим Claude Code по умолчанию блокирует как изменение общих ресурсов, а в обычном режиме спрашивает на каждый вызов. Снимать запрос стоит только с `cats_insert`: он идемпотентен по ключу, а ошибочную запись можно удалить. `cats_change`, `cats_delete` и `cats_release` меняют уже внесённые часы без отмены (`cats_release` сразу утверждает), поэтому их лучше явно оставить с подтверждением. Правило пишется в `.claude/settings.local.json` того каталога, где вы работаете с таймшитом, а не в `~/.claude/settings.json` для всех проектов:

   ```json
   {
     "permissions": {
       "allow": ["mcp__sap-cats__cats_insert"],
       "ask": [
         "mcp__sap-cats__cats_change",
         "mcp__sap-cats__cats_delete",
         "mcp__sap-cats__cats_release"
       ]
     }
   }
   ```

   Правило `allow` снимает запрос в любом режиме, `ask` оставляет его и в auto-режиме. Файл заводится руками — Claude сам себе разрешения не выдаёт.

`.env` сервер читает сам, из каталога рядом с `dist/`: Claude Code запускает `node dist/index.js` напрямую, без загрузки окружения. Переменные, заданные в окружении запуска (`-e` при регистрации), важнее `.env`.

### Если не работает

| Симптом | Причина |
|---|---|
| «SAP отклонил учётные данные» (401) | Неверные `SAP_USER`/`SAP_PASSWORD` (кавычки вокруг пароля в `.env` снимаются, но только парные) или пользователь заблокирован |
| «SAP не пустил к узлу» (403) | Узел `/sap/bc/zcats` не активен в SICF этой системы (транспорт не импортирован или узел не активирован) либо нет доступа к нему |
| «Нет связи с SAP: `UNABLE_TO_VERIFY_LEAF_SIGNATURE`», `SELF_SIGNED_CERT_IN_CHAIN` | Node не доверяет сертификату SAP: `NODE_OPTIONS=--use-system-ca` или `NODE_EXTRA_CA_CERTS` в окружении запуска (шаг 4), не в `.env` |
| «Нет связи с SAP: `ENOTFOUND`», `ECONNREFUSED` | Неверный `SAP_CATS_URL` или хост SAP недоступен из этой сети. Прокси встроенный `fetch` Node не использует, пока в окружении запуска не задан `NODE_USE_ENV_PROXY=1` |
| «SAP вернул не JSON» | По адресу отвечает не хендлер, а страница входа или ошибки ICF — проверьте `SAP_CATS_URL` |
| «SAP не ответил за … с» | Хендлер не уложился в `SAP_TIMEOUT_MS`. Результат записи в этом случае неизвестен — сначала `cats_read` |
| Сервер не стартует: «`SAP_…=…`: нужно целое число» | Опечатка в числовой переменной `.env` |
| Сервера нет в списке MCP или старые описания инструментов | Не выполнен `npm run build` или сервер не перезапущен |
| Названия проектов и ТЗ пустые | Сеанс SAP открылся на языке, на котором тексты не ведутся: задайте `SAP_LANGUAGE=RU` |
| Ошибка BAPI про полномочия на табельный номер | Так же не пустит и CAT2 — вопрос к полномочиям пользователя, не к MCP |

## HTTP-режим

По умолчанию сервер работает через stdio: у каждого пользователя свой процесс со своим логином в `.env`. В HTTP-режиме один сервер обслуживает всех, а логин и пароль SAP каждый клиент присылает сам — заголовком `Authorization: Basic` в каждом запросе. Сервер передаёт его в SAP как есть: SAP по-прежнему видит реального пользователя и проверяет его полномочия, служебного пользователя нет.

### Сервер

В `.env` сервера:

```
MCP_TRANSPORT=http
MCP_HOST=0.0.0.0
MCP_PORT=3000
MCP_TLS_CERT=<путь к сертификату сервера, PEM>
MCP_TLS_KEY=<путь к закрытому ключу, PEM>
MCP_ALLOWED_HOSTS=<имя хоста, по которому к серверу обращаются клиенты>
```

`SAP_USER` и `SAP_PASSWORD` остаются пустыми, `SAP_CATS_URL` и `SAP_CLIENT` — как в обычной установке. Доверие к сертификату SAP (`NODE_OPTIONS=--use-system-ca` или `NODE_EXTRA_CA_CERTS`) задаётся в окружении службы, а не в `.env`. Запуск — `npm start`. Чтобы сервер переживал перезагрузку и падения, его запускают службой Windows (например, через NSSM; переменные окружения — в `AppEnvironmentExtra`).

- **Без TLS сервер слушает только `127.0.0.1`/`localhost`** и на другом адресе не стартует: в заголовке пароль SAP. Если HTTPS уже даёт обратный прокси (IIS, nginx) на той же машине — сервер остаётся на `127.0.0.1`, а в `MCP_ALLOWED_HOSTS` пишется внешнее имя. Прокси должен передавать исходный заголовок `Host` (nginx: `proxy_set_header Host $host;`, IIS ARR: `preserveHostHeader`), иначе каждый запрос получит 403.
- Проверяется заголовок `Host` (`MCP_ALLOWED_HOSTS`) — защита от DNS rebinding.
- Сессий нет: каждый POST на `/mcp` обрабатывается отдельно, GET и DELETE получают 405. Все инструменты и так без состояния — пишущие коммитят в том же вызове.
- Тело запроса больше `MCP_MAX_BODY_BYTES` (1 МБ) получает 413. Один кривой запрос сервер не роняет: отказ приходит только этому клиенту.
- В stderr пишется строка на запрос: время, логин SAP, метод MCP, HTTP-статус, длительность. Пароль не пишется никогда; переводы строк и управляющие символы в логине и методе экранируются, так что подделать строку журнала нельзя. Логин в журнале — тот, что прислал клиент: проверяет его SAP при вызове инструмента.

### Клиент (Claude Code)

```bash
claude mcp add --transport http sap-cats --scope user https://<mcp-host>:3000/mcp --header "Authorization: Basic <base64 от логин:пароль>"
```

Строку base64 можно получить в PowerShell: `[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes('логин:пароль'))`. Кавычки именно одинарные: в двойных PowerShell подставит вместо `$…` переменную, и пароль с `$` молча испортится; апостроф внутри пароля удваивается. Заголовок хранится в настройках Claude Code — так же открыто, как пароль в `.env` в режиме stdio. Неверный пароль обнаружится при первом вызове инструмента: SAP ответит 401, инструмент вернёт «SAP отклонил учётные данные».

Коннекторы claude.ai и Claude Desktop с таким сервером не работают: их вызывает облако Anthropic, а не компьютер пользователя, и им нужен OAuth, а не Basic-заголовок.

## Тесты

```bash
npm test
```

Собирает проект и прогоняет `node:test` без обращения к SAP: схемы входных параметров, разбор сообщений и сквозные тесты MCP-сервера против фейкового ICF-хендлера — через stdio (`test/server.test.mjs`) и через HTTP (`test/http.test.mjs`, в том числе что заголовок каждого клиента уходит в SAP свой и что кривой запрос не роняет сервер). Свой `.env` тесты не читают (`SAP_CATS_DOTENV=0`), поэтому проходят и на машине с настроенным HTTP-режимом.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `cats_whoami` | Мой табельный номер, ФИО и оргединица |
| `cats_projects` | Активные проекты и номера ТЗ для `ext.prjct`/`ext.rqsnb`, пара по ключу задачи Трекера (`ytr_key`) |
| `cats_read` | Вывод таймшита за период |
| `cats_summary` | Сводка часов за период по проектам и номерам ТЗ, по статусам и неделям |
| `cats_capacity` | Свободные часы по дням с учётом календаря |
| `cats_validate` | Проверка записей без сохранения (`TESTRUN` + дневной лимит) |
| `cats_insert` | Создание записей, в том числе за несколько дней и по нескольким проектам сразу |
| `cats_change` | Изменение записей: необязательные поля, которых нет в запросе (подробный и краткий текст, единица и вид оплаты, МВЗ-отправитель; время — если часы не меняются), сохраняются; утверждённая запись правится новой версией |
| `cats_delete` | Удаление записей: запись, ни разу не утверждавшаяся, удаляется физически; утверждённая и её новые версии переходят в статус 60 «Сторнировано» (удаление новой версии сторнирует и исходную) |
| `cats_release` | Деблокирование; в этой системе сразу даёт статус 30 «Утверждено» |

Вместо пары проект + номер ТЗ в записи можно передать `ext.ytr_key` — ключ задачи Трекера, MCP сам найдёт пару. Без номера ТЗ обязательно описание `ext.descr`, как в CAT2. `counter` можно передавать без ведущих нулей — MCP дополнит его до 12 знаков.

Клиенту инструменты размечены MCP-аннотациями: чтение и `cats_validate` — `readOnlyHint`, `cats_change`/`cats_delete`/`cats_release` — `destructiveHint`.

Входные и выходные параметры — в `docs/solution.md`, контракт с ABAP-стороной — в `docs/handler-contract.md`.

Каждое обращение к SAP ограничено таймаутом (`SAP_TIMEOUT_MS`, по умолчанию 60 с). Ответ с `LR2` «Транзакцию блокирует пользователь» автоматически повторяется (`SAP_LOCK_RETRIES`, по умолчанию 2, не больше 10): хендлер при ошибке откатывает LUW целиком, а `cats_insert` идемпотентен по ключу, так что повтор ничего не задваивает. Если связь оборвалась уже после отправки пишущего вызова, ошибка прямо говорит, что результат неизвестен.

## Сценарии (MCP prompts)

| Prompt | Что делает |
|---|---|
| `fill_week_like_last` | Заполняет неделю по образцу предыдущей в пределах свободных часов |
| `fill_gaps` | Закрывает недобор до нормы по рабочим дням периода одним проектом |
| `period_close_check` | Сводка перед закрытием периода: недобор, перебор, записи в статусе 10 |

Сценарии только собирают вызовы инструментов. Записывать что-либо они начинают только после того, как пользователь подтвердил итоговую таблицу.

## Состояние

Узел SICF `/sap/bc/zcats` заведён и активен, хендлер `ZCL_CATS_MCP_HANDLER` — в системе. Все десять инструментов (семь по ТЗ, `cats_whoami`, `cats_projects` и `cats_summary` сверх него) проверены на реальных данных, приёмка по требованиям ТЗ проведена — таблица покрытия в `docs/solution.md`. MCP-сервер работает через stdio и HTTP (проверено против SAP в обоих режимах; где будет стоять общий HTTP-сервер — ещё не решено). 2026-09-29 проведён аудит кода и документации, найденное исправлено (в том числе `cats_change` больше не затирает поля записи, которых нет в запросе). Автотесты: `npm test` (Node, 64) и ABAP Unit в системе (23). Порядок работ, решения и открытые вопросы — в `CLAUDE.md`.
