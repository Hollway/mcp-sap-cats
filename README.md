# mcp-sap-cats

MCP-сервер для таймшитов SAP — транзакция CAT2 / CATS. Задача **SAP-18862**.

Чтение и заполнение учёта времени через стандартные `BAPI_CATIMESHEETMGR_*`, вызываемые из собственного ICF-хендлера в целевой SAP-системе.

## Установка

Инструкция для пользователя, который ставит MCP-сервер себе. Сервер работает на вашей машине и ходит в SAP под вашим логином: видите и меняете вы ровно то, что вам доступно в CAT2.

### Что нужно заранее

- **Хендлер в той SAP-системе, где вы вводите часы.** Класс `ZCL_CATS_MCP_HANDLER` и узел SICF `/sap/bc/zcats` приходят одним транспортом. После импорта узел должен быть активен в SICF; если нет, сервер ответит 403 (см. «Если не работает»).
- **Пользователь SAP с доступом к CAT2.** Отдельных полномочий под MCP не нужно: записывать можно ровно тех, кого пускает CAT2.
- **Node.js 20 или новее** (`node -v`) и Claude Code.
- **Корневой сертификат корпоративного CA** в формате PEM — у SAP-хоста самоподписанный сертификат.

### Шаги

1. Получить код — клонировать репозиторий или скопировать папку, например в `C:\Tools\mcp-sap-cats`.
2. Собрать:

   ```bash
   npm install
   npm run build
   ```

   В PowerShell — `npm.cmd`, если политика выполнения блокирует `.ps1`-обёртки. За корпоративным прокси npm должен знать прокси (`npm config set proxy …` / `https-proxy …`).
3. Скопировать `.env.example` в `.env` рядом с `package.json` и заполнить: адрес узла, мандант, свой логин и пароль SAP, профиль ввода, путь к сертификату (`NODE_EXTRA_CA_CERTS`), `NO_PROXY` с хостом SAP. Пароль лежит в файле открытым текстом — файл личный, никому не пересылать и не класть в git (`.env` уже в `.gitignore`).
4. Зарегистрировать сервер в Claude Code:

   ```bash
   claude mcp add sap-cats --scope user -- node C:\Tools\mcp-sap-cats\dist\index.js
   ```

   В PowerShell — `claude.cmd`. `claude mcp add-json` там не подходит: PowerShell ломает кавычки в JSON-аргументе. Править `claude_desktop_config.json` руками тоже бесполезно — приложение перезаписывает его при перезапуске.
5. Перезапустить Claude Code и попросить «кто я в SAP» — должен сработать `cats_whoami` и вернуть ваш табельный номер.
6. Если Claude Code работает в auto-режиме, пишущие инструменты (`cats_insert`, `cats_change`, `cats_delete`, `cats_release`) он по умолчанию блокирует как изменение общих ресурсов. Чтобы разрешить, добавьте их в `permissions.allow` своих настроек (`~/.claude/settings.json` — для всех проектов, `.claude/settings.local.json` — для одного):

   ```json
   {
     "permissions": {
       "allow": [
         "mcp__sap-cats__cats_insert",
         "mcp__sap-cats__cats_change",
         "mcp__sap-cats__cats_delete",
         "mcp__sap-cats__cats_release"
       ]
     }
   }
   ```

   Файл заводится руками — Claude сам себе разрешения не выдаёт. В обычном режиме вместо этого будет запрос подтверждения на каждый вызов.

`.env` сервер читает сам, из каталога рядом с `dist/`: Claude Code запускает `node dist/index.js` напрямую, без загрузки окружения.

### Обновление

```bash
git pull
npm run build
```

Затем перезапустить MCP-сервер (или Claude Code): до перезапуска клиент видит старые инструменты и их описания.

### Если не работает

| Симптом | Причина |
|---|---|
| «SAP отклонил учётные данные» (401) | Неверные `SAP_USER`/`SAP_PASSWORD` или пользователь заблокирован |
| «SAP не пустил к узлу» (403) | Узел `/sap/bc/zcats` не активен в SICF этой системы (транспорт не импортирован или узел не активирован) либо нет доступа к нему |
| Ошибка сертификата (`self-signed certificate`, `unable to verify`) | Не задан или не тот `NODE_EXTRA_CA_CERTS` |
| «SAP не ответил за … с», `fetch failed` | Запрос ушёл через прокси: добавьте хост SAP в `NO_PROXY` |
| Сервера нет в списке MCP или старые описания инструментов | Не выполнен `npm run build` или сервер не перезапущен |
| Ошибка BAPI про полномочия на табельный номер | Так же не пустит и CAT2 — вопрос к полномочиям пользователя, не к MCP |

## Тесты

```bash
npm test
```

Собирает проект и прогоняет `node:test` без обращения к SAP: схемы входных параметров, разбор сообщений и сквозной тест MCP-сервера против фейкового ICF-хендлера (`test/server.test.mjs`).

## Отладка

```bash
npm run dev
```

Откроет MCP Inspector: список инструментов виден сразу, вызывать можно руками, без перезапуска Claude.

Всё, что попадает в stdout, — это протокол. Отладочный вывод только через `console.error`.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `cats_whoami` | Мой табельный номер, ФИО и оргединица |
| `cats_projects` | Активные проекты и номера ТЗ для `ext.prjct`/`ext.rqsnb`, пара по ключу задачи Трекера (`ytr_key`) |
| `cats_read` | Вывод таймшита за период |
| `cats_summary` | Сводка часов за период по проектам и номерам ТЗ, по статусам и неделям |
| `cats_capacity` | Свободные часы по дням с учётом календаря |
| `cats_validate` | Проверка записей без сохранения (`TESTRUN` + дневной лимит) |
| `cats_insert` | Создание записей, в том числе за несколько дней и по нескольким проектам сразу |
| `cats_change` | Изменение записей; утверждённая запись правится новой версией |
| `cats_delete` | Удаление записей: неутверждённые удаляются физически, утверждённые переходят в статус 60 «Сторнировано» |
| `cats_release` | Деблокирование; в этой системе сразу даёт статус 30 «Утверждено» |

Вместо пары проект + номер ТЗ в записи можно передать `ext.ytr_key` — ключ задачи Трекера, MCP сам найдёт пару. Без номера ТЗ обязательно описание `ext.descr`, как в CAT2.

Входные и выходные параметры — в `docs/solution.md`, контракт с ABAP-стороной — в `docs/handler-contract.md`.

Каждое обращение к SAP ограничено таймаутом (`SAP_TIMEOUT_MS`, по умолчанию 60 с). Ответ с `LR2` «Транзакцию блокирует пользователь» автоматически повторяется (`SAP_LOCK_RETRIES`, по умолчанию 2): хендлер при ошибке откатывает LUW целиком, а `cats_insert` идемпотентен по ключу, так что повтор ничего не задваивает.

## Сценарии (MCP prompts)

| Prompt | Что делает |
|---|---|
| `fill_week_like_last` | Заполняет неделю по образцу предыдущей в пределах свободных часов |
| `fill_gaps` | Закрывает недобор до нормы по рабочим дням периода одним проектом |
| `period_close_check` | Сводка перед закрытием периода: недобор, перебор, записи в статусе 10 |

Сценарии только собирают вызовы инструментов. Записывать что-либо они начинают только после того, как пользователь подтвердил итоговую таблицу.

## Состояние

Узел SICF `/sap/bc/zcats` заведён и активен, хендлер `ZCL_CATS_MCP_HANDLER` — в системе. Все десять инструментов (семь по ТЗ, `cats_whoami`, `cats_projects` и `cats_summary` сверх него) проверены на реальных данных, приёмка по требованиям ТЗ проведена — таблица покрытия в `docs/solution.md`. Автотесты: `npm test` (Node) и ABAP Unit в системе. Порядок работ, решения и открытые вопросы — в `CLAUDE.md`.
