# Контракт ICF-хендлера

Node-сторона написана против этого контракта, ABAP-класс `ZCL_CATS_MCP_HANDLER` (`abap/`) его реализует. Изменения контракта вносятся здесь, в `src/index.ts` и в хендлере одновременно; Node-сторона контракта покрыта `npm test` (фейковый хендлер в `test/server.test.mjs` и `test/http.test.mjs`).

## Узел

Базовый путь: `/sap/bc/zcats` в целевой SAP-системе.

**Данные логона в узле не сохраняются.** Авторизацию выполняет SAP по заголовку `Authorization: Basic`. MCP-сервер берёт его из своего `.env` (режим stdio) или передаёт заголовок клиента как есть (режим HTTP) — хендлеру разницы нет. Для записи полномочия вызывающего пользователя определяют, чьи табельные номера ему доступны (проверяет BAPI). Чтение (`/read`, `/capacity`) полномочия на табельный не проверяет — решение проекта, см. `CLAUDE.md`.

## Общее

- Только `POST` с `Content-Type: application/json`, тело запроса и ответа — JSON, UTF-8. Другой метод — 405, другой тип тела — 415: межсайтовая форма из браузера (`text/plain`) до маршрутов не доходит.
- Мандант приходит в `sap-client`, язык сеанса — в `sap-language` (если задан `SAP_LANGUAGE`).
- Ответ всегда содержит `messages` — разобранный `BAPIRET2`:
  ```json
  { "type": "E", "id": "CATS", "number": 42, "text": "...", "row": 2 }
  ```
- NUMC-поля (`number`, `pernr`, `rqsnb`, `orgeh`) `/ui2/cl_json` отдаёт **числами** без ведущих нулей: Node сам дополняет `pernr` до 8 знаков, а номер сообщения печатает как в SE91 (`LR002`). `counter` — CHAR 12 и приходит строкой с нулями; Node дополняет нулями и то, что пришло от пользователя.
- `row` — номер записи во входном массиве, начиная с 1. `0` — сообщение относится ко всему вызову. Поля `messages`, `committed` и массивы результатов присутствуют всегда, даже пустые (`/ui2/cl_json` вызывается без `compress`).
- Неверные учётные данные — HTTP 401, нет доступа к самому узлу — 403 (оба отдаёт ICF до хендлера). Хендлер сам отвечает 404 на неизвестный маршрут, 400 на неверный период в `/capacity` и 500 на необработанное исключение — тоже JSON с `messages` (`MCP000`). Прикладные ошибки, включая отсутствие полномочий на табельный номер при записи, приходят с HTTP 200 и типом `E` в `messages`.

## Маршруты

| Метод | Путь | BAPI | Фиксация |
|---|---|---|---|
| POST | `/read` | чтение `CATSDB` | — |
| POST | `/capacity` | `CATSDB` + `DATE_CONVERT_TO_FACTORYDATE` (календарь `BY`); период не длиннее 10 лет; даты, которых нет в календаре, — `W MCP007` | — |
| POST | `/validate` | `BAPI_CATIMESHEETMGR_INSERT`, `TESTRUN = 'X'` + дневной лимит | нет |
| POST | `/insert` | `BAPI_CATIMESHEETMGR_INSERT` + дневной лимит | `BAPI_TRANSACTION_COMMIT` в том же вызове |
| POST | `/change` | `BAPI_CATIMESHEETMGR_CHANGE` + дневной лимит (часы изменяемых записей не складываются с новыми). Запись строится от текущей строки `CATSDB` этого `pernr`: незаданные необязательные поля и подробный текст сохраняются (время начала и конца — только если часы не меняются); `counter`, которого у табельного нет, — `E MCP006` | то же |
| POST | `/delete` | `BAPI_CATIMESHEETMGR_DELETE` — запись, ни разу не утверждавшаяся (`10`), удаляется физически, утверждённая (`30`) и её новые версии переходят в `60`; `deleted` — переданные `counters` после коммита | то же |
| POST | `/release` | `BAPI_CATIMESHEETMGR_CHANGE`, `RELEASE_DATA = 'X'`, ресенд строк статуса `10` из `CATSDB` (по `counters` — только этого `pernr`); процедура утверждения не настроена, итог — статус `30`. `released` заполняется только после коммита, в ответе есть `committed` | то же |
| POST | `/whoami` | `PA0105` (подтип `0001`) по `sy-uname`, `PA0001`, `T527X` | — |
| POST | `/projects` | `ZBTPRJCT`/`ZBTPRJCTT`; с `prjct` — ТЗ из `ZBTPROJECT`/`ZBTREQSPT` и `ZYTRPROJ`; с `ytr_key` — пара из `ZYTRPROJ`, затем `ZBTPROJECT` | — |

Дневной лимит, `/capacity` и `total_hours` в `/read` не учитывают записи в статусах `50` (старая версия после правки утверждённой записи) и `60` (сторнировано): обе сохраняют часы в `CATSDB`. Лимит блокирует, только если часы дня после записи выше нормы **и** выше, чем были до неё: день, уже внесённый сверх нормы (в CAT2 лимитов нет), можно править без роста часов. Суммы за период (`total_hours`, `total_free`) считаются в типе без предела 999,99 ч. Правка записи в статусе `30` создаёт новую версию с новым `COUNTER` — `/change` возвращает в `changed` именно его.

Подробный текст записи — поле `longtext` (строка с переводами строк) в `records` маршрутов `/validate`, `/insert`, `/change`; уходит в параметр `LONGTEXT` BAPI (`BAPICATS8`, по 132 символа; пробел на месте разреза переносится в начало следующей строки, иначе SAP его теряет). `/read` возвращает признак `longtext` и сам текст в `longtext_text` (абзацы через перевод строки); язык текста — последней правки. `/change` и `/release` передают `TEXT_FORMAT_IMP = 'ITF'` и пересылают существующий подробный текст, если новый не задан, — иначе BAPI его удалит. ITF-разметку (`<(>…<)>`, `,,`, `<xx>`) хендлер не кодирует и не раскодирует.

`cats_summary` отдельного маршрута не имеет: сводку считает MCP по ответу `/read`.

`ext.ytr_key` (ключ задачи Трекера) хендлеру не передаётся: MCP заранее переводит его в `prjct` + `rqsnb` через `/projects`. Описание (`ext.descr`) при заданном номере ТЗ можно не передавать — его подставит пользовательский выход CATS `ZXCATU02`.

**Фиксация обязана происходить внутри того же обращения к хендлеру, что и вызов BAPI.** При stateless HTTP каждый запрос — новая LUW, и запись пропадёт молча.

## Идемпотентность

`idempotency_key` из запроса раскладывается в `BAPICATS1`:

- `EXTSYSTEM` — постоянное значение, например `MCP`
- `EXTAPPLICATION` — `CATS`
- `EXTDOCUMENTNO` — сам ключ

Перед вставкой хендлер проверяет, нет ли в `CATSDB` записи того же табельного с теми же `EXTSYSTEM`/`EXTAPPLICATION`/`EXTDOCUMENTNO`. Если есть — возвращает её `COUNTER` и сообщение `S MCP001`, ничего не создавая, даже если набор записей в запросе другой: ключ обозначает один вызов, для нового набора нужен новый ключ.

## Z-поля

`ZZRQSNB`, `ZZPRJCT`, `ZZDESCR`, `ZZORGUNIT` передаются в `EXTENSIONIN` структурой `BAPI_TE_CATSDB`. Она уже существует, доработка словаря не требуется.
